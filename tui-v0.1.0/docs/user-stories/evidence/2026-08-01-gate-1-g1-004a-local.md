## Scénario positif

Une enveloppe `hermes-console/policy-decision/v1\0` signe le tuple v1 complet avec `policyVersion=1`,
`algorithm=Ed25519`, `actionKind=fixture.marker.write`, portée explicite, payload SHA-256 exact,
approbateur, TTL de 60 s et nonce 128 bits. L'enforcer vérifie la signature et consomme atomiquement
`keyId\0decisionId\0nonce` avant d'exécuter le compteur synthétique : `markerWrites=1`.

## Scénarios négatifs exécutés

```text
policy indisponible       -> DECISION_POLICY_UNAVAILABLE, effet absent
policy absente            -> DECISION_POLICY_DENIED, effet absent
payload altéré            -> DECISION_PAYLOAD_MISMATCH
scopeId divergent         -> DECISION_SCOPE_MISMATCH
rejeu                     -> DECISION_REPLAY
expiration / futur        -> DECISION_EXPIRED / DECISION_NOT_YET_VALID
domaine invalide          -> DECISION_DOMAIN_INVALID
champ inconnu             -> DECISION_ENVELOPE_INVALID
approbateur absent        -> DECISION_APPROVER_REQUIRED
algorithme/clé/signature  -> refus dédiés
outcome deny              -> DECISION_DENIED
```

Le replay est également refusé après un effet synthétique qui lève une exception : la consommation
du nonce précède l'effet.

## Limites et verdict

Le code couvre `P-CODE`/`P-INT` local uniquement. Il n'y a pas de policy store réelle, de branchement
au runner ou à `respond-approval`, de runtime Hermes, de P-SEC indépendante, de P-E2E, ni de preuve
d'absence de contournement sur une cible. Verdict : `BLOQUÉE` pour l'acceptation complète G1-004.
